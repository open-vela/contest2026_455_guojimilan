# 2026-09-08 按键 + DCC-101 步进电机翻盖控制打通（AI 辅助开发日志）

## 目标
在 openvela(NuttX) 固件上实现：按键一键控制步进电机开/合垃圾桶盖（0°↔90°），OLED 实时显示状态。

## 过程

### 1. 裸机先行验证（Keil + GD32 官方库）
- 参考 23e 电赛代码的 DCC-101 协议：115200-8N1，11 字节帧
  `AA 55 | 01 | 11 | 05 | 方向 | 速度(2B) | 步数(2B,小端) | 校验和`
- 16384 步/圈 → 90° = 4096 步
- 接线：PA2(USART1_TX) → DCC-101 RX1，12V 独立供电，共地
- 裸机一次成功：按按键电机转 90°

### 2. NuttX 侧连环踩坑（每一步都有证据链）
| 现象 | 根因 | 修复 |
| ---- | ---- | ---- |
| 板载 User Key(PA0) 按了没反应 | 裸机正常、寄存器配置正确(A0/U1/I49151)，NuttX 下电平不变（未解之谜） | 换 PB12 外接按键模块，一次成功 |
| 屏幕冻结、按啥都没反应 | NuttX 串口 read() 无数据永久阻塞，主循环卡死（OLED"无响应"是假象） | read() → poll(50ms)+read，主循环恢复节拍 |
| 按键通了但电机不转 | defconfig 没启用 USART1，/dev/ttyS1 不存在，open() 静默失败 | defconfig 追加 `CONFIG_GD32F4_USART1=y`，电机立即转 |
| OLED 标题 "VM FLASH OK" 显示成 "VM LASH OK" | 字库缺 B/C/F/J/Q/Z/v/x/y | 补全 5x7 字模表 |
| 翻盖收回方向不对 | DCC-101 协议方向字节是 0x01顺/0x00逆，误写成 0x02 | 修正为 0x00=逆时针 |

### 3. 旋转编码器尝试（放弃）
- EC11 接 PB14/PB15，下降沿计数 + B 相判向，代码已实现并入裸机验证
- 用户手上编码器硬件不良（拧动信号异常），决定弃用，代码已从最终版移除
- 经验：EC11 每挡位角度(2°)太小观感"没动"，需调到 5~15°；C90 编译器要求变量声明全在块首

### 4. 最终形态
- 按一下按键：翻盖 0°→90°（开），再按 90°→0°（合）
- OLED: `LID:OPEN 90` / `LID:CLOSE 0`，LED 心跳闪烁
- K230 USART0 坐标帧解析逻辑保留（poll 非阻塞），可扩展视觉自动开盖

## 关键经验沉淀
1. NuttX 调试先看"主循环活没活"（LED 心跳），冻结的屏幕会制造假象
2. NuttX 外设（USART/I2C）defconfig 默认大多关闭，open() 失败必须打日志
3. 裸机验证法效率极高：同一份逻辑 Keil 秒级烧录验证硬件，再搬进 NuttX 排除软件变量
4. VirtualBox USB 代理卡死只能重启 Windows 解决；Keil 与虚拟机抢 ST-Link 需重新 usbattach
